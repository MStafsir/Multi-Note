# Task 49.12c — Atomic Hard-Delete TOCTOU Fix

**Agent**: full-stack-developer
**Date**: 2025-07-09

## Summary

Fixed the TOCTOU (Time-of-Check-Time-of-Use) vulnerability in `hardDeleteNode()` by extracting it to a shared utility and restructuring for atomicity using Prisma interactive transactions.

## Problem

The `hardDeleteNode()` function existed in TWO files with identical logic:
1. `/src/app/api/trash/purge/route.ts`
2. `/src/app/api/trash/auto-purge/route.ts`

The vulnerable pattern was:
1. `findFirst` with ownerId check (authorization)
2. Delete side effects (disk file, metadata, versions, notes, shares, tags, activity) — **irreversible**
3. Final `deleteMany` with ownerId re-check (atomic verification)

**TOCTOU risk**: If ownership changes between step 1 and step 3, the side effects (disk file deletion, metadata deletion) are irreversible even though the node wasn't actually deleted.

## Solution

Created `/src/lib/hard-delete-node.ts` with atomic pattern:

1. **Pre-transaction**: `findFirst` to gather file paths for disk cleanup (NOT for authorization — just info gathering)
2. **Transaction (atomic)**:
   - `deleteMany` with `{id, ownerId}` FIRST — this is the atomic ownership verification
   - If `count === 0`, abort transaction (ownership changed) — no side effects occurred
   - Only after successful node delete, clean up orphaned side-effect data (metadata, versions, notes, etc.)
3. **Post-transaction**: Disk file cleanup only if transaction succeeded (filesystem can't rollback)

This ensures that if ownership changes, the transaction returns `count=0` and NO side-effect deletions occur (neither DB records nor disk files).

## workspaceId Parameter Design

- `undefined` → don't filter by workspace (default for purge routes, deletes across all workspaces)
- `null` → filter for personal workspace only (`workspaceId IS NULL`)
- `string` → filter for team workspace only (`workspaceId = value`)

## Files Changed

1. **Created**: `/src/lib/hard-delete-node.ts` — shared atomic utility with `HardDeleteResult` interface
2. **Updated**: `/src/app/api/trash/purge/route.ts` — removed hardcoded `hardDeleteNode`, imports from shared utility
3. **Updated**: `/src/app/api/trash/auto-purge/route.ts` — removed hardcoded `hardDeleteNode`, imports from shared utility

## Callers Updated

Both route callers now use `result.deletedCount > 0` to check if the node was actually deleted, instead of just incrementing `deletedCount` unconditionally. This correctly handles the case where ownership changed and the node was not deleted.
